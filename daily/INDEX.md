## 今日（2026-09-04）分析摘要

### 🎯 `check_preempt_curr` — 调度器抢占检查统一入口

**位置**：`kernel/sched/core.c:836-859`（Linux v4.19）

**一句话概括**：当新任务入队到运行队列时，通过**「同类委派调度类回调 + 跨类优先级链表遍历」**的双层策略判断是否需要抢占当前 CPU 上正在运行的任务，并设置 `TIF_NEED_RESCHED` 标志触发软抢占。

**核心知识点**：

1. **调度类优先级链表顺序**：`stop → dl → rt → fair → idle`（高→低）
2. **同类委派方向**：用 `rq->curr->sched_class` 的回调而非新任务的，保证上下文热状态读取正确
3. **CFS 判定公式**：`vdiff = curr.vruntime - se.vruntime`，与 `wakeup_gran(se)` 比较（不对称的权重换算，刻意惩罚 lighter task 维护 nice 语义）
4. **抢占实际生效时机**：TIF_NEED_RESCHED 是软标志，仅在中断返回、syscall 返回、preempt_enable 末尾等抢占点才会发生 context switch
5. **四大调用场景**：任务唤醒（ttwu）、Fork 新进程、CPU 亲和性迁移、NUMA 任务互换
6. **SMP 跨 CPU 抢占的 IPI polling 抑制**：目标 CPU 在 polling idle 时只设标志不发 IPI，节省功耗
7. **rq_clock_skip_update 微优化**：判定成功后跳过冗余的 sched_clock 读取，因为 schedule() 内部会立即更新
